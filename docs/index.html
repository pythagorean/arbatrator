Arbatrate

A remote browser appliance to receive all types of resources

Run Chromium on a well-connected machine and use it from a thin laptop. The picture comes through waypipe, the sound comes as Opus, and media can be handed off to a player on your own machine.

Install Source on GitHub

What it does

A browser that lives elsewhere

Chromium runs in a Podman container on a VM or server, with its own persistent profile and its own network location. Your laptop only draws the window.

Picture and sound

waypipe carries the window to your Wayland desktop. The browser's sound is captured from PipeWire and streamed to you as low-latency Opus, over the same SSH connection.

Media to your own player

Right-click a video and choose Play locally. The appliance fetches it and streams it to mpv on your machine, picking up where you were.

Protected media stays put

DRM-protected media is never handed off. It plays in the remote browser only.

How it fits together

Install

There are two machines: your machine (the client, such as a laptop) and the appliance host (usually a VM with a good connection). You install Arbatrate on your machine, and it installs itself on the host over SSH.

  1. Prepare the appliance host. It needs rootless podman 4.3 or newer and waypipe, and you need to be able to log in to it with an SSH key.
    Fedora
    sudo dnf install podman waypipe
    Debian, Ubuntu
    sudo apt install podman waypipe
    Let the SSH user keep a runtime directory without a desktop login (systemd hosts, once): 
    sudo loginctl enable-linger "$USER"
  2. Prepare your machine. It needs a Wayland desktop, git, make, ssh, Python 3.11 or newer, mpv, and waypipe (the same version as on the host).
    Fedora
    sudo dnf install git make openssh-clients python3 mpv waypipe
    Debian, Ubuntu
    sudo apt install git make openssh-client python3 mpv waypipe
    Arch
    sudo pacman -S git make openssh python mpv waypipe
  3. Download and install Arbatrate. 
    git clone https://github.com/pythagorean/arbatrator.git
    cd arbatrator && make install
    This puts arbatrate in ~/.local/bin; make sure that is on your PATH.
  4. Tell it where the host is. 
    mkdir -p ~/.config/arbatrate && cp client/config.example.toml ~/.config/arbatrate/config.toml
    Edit that file and set host to what you would type after ssh, such as host = "you@browser-vm". Every other setting is optional and explained in the file.
  5. Install the appliance on the host. This copies it over and builds the image there; the first build takes a few minutes. 
    arbatrate install-host
  6. Check both ends. Anything marked MISSING or DIFFER says what to fix. 
    arbatrate doctor
  7. Open the browser. 
    arbatrate
    Close the window or press Ctrl-C to end the session. Your profile is kept for next time; arbatrate --profile work opens a separate one.

Updating

cd arbatrator && git pull && make install && arbatrate install-host

Handing media off

  • Right-click a video or audio element: Play locally.
  • Right-click a link: Play link locally.
  • Right-click the page, or click the Arbatrate toolbar button: Play this page's media locally.

In the default relay mode, the appliance fetches the media with the browser's cookies and streams it to your player, so sites only ever see the appliance. In local mode, your player fetches the URL itself. Either way, protected media is refused.

On a slow connection

Almost all the bandwidth goes to the picture. Stronger compression usually helps on a slow link. Add this to your configuration:

[waypipe]
options = ["--compress=zstd=7"]

For handed-off video, relay_format and relay_transcode in the same file let the appliance send a smaller stream.

How it behaves

  • Nothing is restarted. If any part of a session ends, the whole session ends and tells you which part it was.
  • One connection. Everything travels over a single SSH connection; the host needs nothing listening but sshd.
  • Chromium's own sandbox stays on inside the container.
